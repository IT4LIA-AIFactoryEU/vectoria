# `etc/hpc/` — Leonardo HPC Runtime

Generated SLURM script, GPU-tuned Vectoria config, and helper scripts used when Vectoria runs on Leonardo. **Deployment is automated** — see [`ansible/README.md`](../../ansible/README.md). This folder documents what gets generated and the GPU-specific tuning.

```
Leonardo HPC — 1 SLURM node, 4× A100 64 GB
  ├─ vLLM      GPU 0,1   port 8000  (internal, serves the LLM)
  ├─ Vectoria  GPU 2,3   port 8080  → tunnel → localhost:8081
  └─ OpenWebUI CPU       port 8090  → tunnel → localhost:8082
```

## Files

| File | Where to run | Purpose |
|---|---|---|
| `vectoria_hpc_launcher.job` | Leonardo login | SLURM batch script. Generated by Ansible at deploy time — not committed to the repo. Logs to `~/vectoria_hpc-<job_id>.out`. |
| `default_config.yaml` | (read by the job) | GPU-tuned Vectoria config. Generated by Ansible at deploy time from `ansible/roles/vectoria/vars/config.yml` — not committed to the repo. |
| `leonardo_connect.sh` | Your PC | CINECA cert renewal (`cert` subcommand). Tunnels are opened by `ansible/connect.yml`; the `vectoria` subcommand is a manual fallback. |

Deployment is Ansible-only — there is no manual setup path.

## Config — HPC vs Local

| Setting | Local (CPU) | HPC (GPU) | Reason |
|---|---|---|---|
| `extraction.backend` | `pypdf` | `docling` | ML-based, handles scanned PDFs |
| `chunking.method` | `recursive` | `semantic` | Topic-aware; needs GPU |
| `chunking.semantic_device` | — | `cuda` | GPU sentence embeddings |
| `vector_store.device` | `cpu` | `cuda` | GPU embeddings at index + query |
| `reranker.device` | `cpu` | `cuda` | GPU CrossEncoder |
| LLM backend | Ollama / llama-server | vLLM (tensor parallel) | Multi-GPU throughput |

### Semantic chunking

Uses a sentence-transformer (`all-MiniLM-L6-v2` by default) to detect topic boundaries. More coherent chunks than fixed-size; impractical on CPU, negligible cost on GPU.

```yaml
chunking:
  method: semantic
  chunk_overlap: 64
  semantic_device: cuda
  semantic_breakpoint_threshold_type: percentile
  semantic_breakpoint_threshold_amount: 70.0
  semantic_max_chunk_size: 512    # safety cap: split recursively if exceeded
```

### Retrieval parameters

| Parameter | Value | Description |
|---|---|---|
| `chunk_size` | 512 (cap) | Tokens per chunk after semantic split |
| `chunk_overlap` | 64 | Overlap on recursive fallback |
| `top_k` | 3 | Candidates before reranking |
| `reranked_top_k` | 3 | Chunks sent to the LLM |
| `max_tokens` | 512 | Max tokens in the LLM response |

## Changing the LLM Model

Edit `ansible/roles/vectoria/vars/config.yml`, then re-run [`ansible-playbook -i inventory deploy.yml`](../../ansible/README.md#quick-start). The playbook handles re-download and resubmission.

GPU sizing on A100 64 GB:

| Parameters | GPUs | `vllm_tensor_parallel` | Example |
|---|---|---|---|
| ~7–13B | 1 | 1 | `meta-llama/Llama-3.1-8B-Instruct` |
| ~24–31B | 2 | 2 | `google/gemma-4-31B-it` |
| ~70B | 4 | 4 | `meta-llama/Llama-3.1-70B-Instruct` |

## Model Cache

| Cache | Path | Populated by |
|---|---|---|
| Vectoria models (embedder, reranker, docling) | `$SCRATCH/hf_vectoria` | `deploy.yml` |
| LLM weights | `$SCRATCH/hf_models` | `deploy.yml` (via `download_LLMs.yml`) |
| Tiktoken encodings | `~/.tiktoken_cache` | `deploy.yml` |

Compute nodes have no internet — everything must be cached before the job runs. The playbook handles this automatically.
